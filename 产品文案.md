## One-liner

The same fillable PDF form, filled 200 times from a spreadsheet. FormFillBatch does it in one run — one flattened PDF per row — then re-opens every output and reads the values back to prove they landed.

## The problem

Vendor packets, intake forms, applications, agreements: someone in every office re-types the same form from the same spreadsheet, row by row, and the errors are found by the *recipient*. Mail merge doesn't do PDF forms, and the tools that do are either $150+ desktop suites or per-document web services you upload client data to.

## What it does

- Template: any fillable (AcroForm) PDF. Data: CSV or Excel, column headers matched to the form's field names — a built-in field lister shows you exactly what to name your columns
- One output PDF per row, named from a column you choose (`001_Alice_Nguyen.pdf`)
- Text fields and checkboxes (set from the form's own export values)
- Outputs are **flattened properly**: values are drawn into the page content itself, so they print, archive and read back identically everywhere — not trapped in form fields that half the viewers render differently
- **Read-back verification:** every produced PDF is re-opened and every value is compared against its spreadsheet row; failures are listed by row in the report, and the batch only PASSes when every row verifies
- Honest reporting: data columns with no matching field and form fields with no data column are both listed, never silently dropped
- Fully offline — client data never leaves your machine

## Measured (seeded acceptance test, 12/12 checks passed)

- Seeded form (2 text fields + checkbox) × 3-row CSV → 3 flattened PDFs, every value readable in the extracted text of its output, zero form fields left after flattening
- Extra spreadsheet column correctly reported as unmatched; filenames taken from the name column as specified

## Honest limits

- AcroForm (fillable) PDFs only — a form with no fields is rejected with a clear explanation
- XFA forms (some government PDFs) are detected and flagged unsupported rather than half-filled
- Checkbox states are set from the form's export values but can't be text-verified after flattening; the report says to spot-check one output if checkboxes are critical
